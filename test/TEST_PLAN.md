# Lexi テスト設計

## 優先順位

1. ヘルスチェックとルーティング
2. 認証済み・未認証のController挙動
3. APIの成功レスポンスとエラー形式
4. サービス層の入力検証と権限判定
5. Slick/Evolutionsを使うDB統合テスト

## 方針

- Controllerテストは `FakeRequest` と `stubControllerComponents` を使い、認証Actionはテスト用の差し替えを用意する。
- ルーターテストでは主要なHTTPメソッド、パス、ステータスコードだけを検証する。
- サービス・リポジトリの単体テストはDBに接続せず、境界をモックまたはスタブ化する。
- DB統合テストは専用のテストDBとEvolutionsを適用し、開発DBを破壊しない。
- Scala.jsの画面テストは状態遷移とAPIクライアントを優先し、Playwrightのブラウザ操作は重要導線に限定する。

## 最初に実装するテスト

- `GET /health` が `200` と期待するContent-Typeを返す（実装済み）
- 未認証ユーザーが保護された画面/APIへアクセスした場合の `401`（`AuthenticatedAction` で実装済み）
- サインイン成功・失敗時のレスポンス
- 代表的な単語検索APIの成功・空結果・入力エラー
- テストDBへ接続し、Evolutionsで作成される `Roles` テーブルを検証（実装済み）
- `WordRepository` の作成・取得・削除をテストDBで検証（実装済み）
- Playwrightでヘルスチェック、ホーム画面、サインイン画面をChromium上で検証（実装済み）
- Playwrightでゲスト閲覧導線と新規登録フォームのパスワード検証を確認（実装済み）
- Playwrightで新規登録後のログイン成功とホーム遷移を確認し、テストユーザーを後片付けする（実装済み）
- Playwrightで認証済みユーザーが新しい言葉・タグ・読みを投稿し、詳細画面へ遷移できることを確認する（実装済み）
- Playwrightで投稿フォームの下書きがリロード後に復元され、投稿成功後に削除されることを確認する（実装済み）
- 一括既読APIが未認証リクエストを拒否し、他ユーザーの通知を更新しないことを確認する（実装済み）
- Scala.jsで一括既読後の未読有無と未読件数が同時に更新されることを確認する（実装済み）
- Playwrightで通知の一括既読、未読バッジの消去、再読込後の永続化を確認する（実装済み）
- Playwrightで390px幅とPC幅の引用操作行、投稿・キャンセル・下書き破棄を確認する（実装済み）
- DB統合テストでWeb Push購読の複数ブラウザ保持、ユーザー境界、論理削除、恒久的配信失敗の無効化を確認する（実装済み）
- PlaywrightでルートスコープのService Worker配信と、Web Push無効時の通知設定表示を確認する（実装済み）
- 実ブラウザと開発用VAPID鍵で、権限許可、Push受信、クリック遷移と既読化、ログアウト時の購読解除を手動確認する

## セキュリティ回帰テスト

2026-08-29の静的監査で確認した未実装の回帰テストを、次の順で追加する。

- `X-Forwarded-For` をクライアントが指定しても、信頼プロキシ以外からクライアントIP判定を変更できない（実装済み）
- 偽装した転送ヘッダーをリクエストごとに変更しても、サインインとサジェストのレート制限を回避できない
- 未許可の `Host` が拒否され、許可したOrigin以外にはCORSレスポンスヘッダーを返さない
- 公開ページネーションAPIが `limit <= 0` と上限超過を安全な範囲へ正規化する（共通境界テスト実装済み）
- JWTのサーバー側世代を更新した後、それ以前のJWTを保護APIで再利用できない（DB統合テスト実装済み）
- 新規登録・パスワード変更APIが8文字未満またはbcrypt上限の72バイト超過を拒否する（共通境界テスト実装済み）
- CSPの `script-src` から `unsafe-inline` と `unsafe-eval` を除去した状態で各Scala.js画面が動作する（設定済み、E2E確認待ち）
- 依存監査でHigh以上の新規脆弱性、または到達可能な既知脆弱性を検出した場合にCIを失敗させる

## テストDB

- 接続先は `lexi_test_db` とし、開発用の `lexi_db` を使わない。
- 設定は `conf/application.test.conf`、初回作成SQLは `db/create-test-database.sql` に置く。

## 既存サンプル

`backend/controllers/HomeControllerSpec.scala` は現行のホーム画面をDB接続なしで描画することを検証している。Play初期サンプル由来の `Welcome to Play` 文言検証は行わない。
